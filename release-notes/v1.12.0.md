Починка после блокировок 16.11: ядро синхронизировано с tg-ws-proxy 1.12.0 (Flowseal).

• Cloudflare по TLS и по HTTP сам: многие провайдеры теперь режут TLS к доменам Cloudflare-прокси. Приложение пробует порт 443 (TLS) и порт 80 (обычный ws://) одновременно и запоминает, что работает в этой сети — на Wi-Fi и на мобильном отдельно. Галочка «только порт 80» больше не нужна.
• CF Worker так же: домен без схемы пробуется и по TLS, и по HTTP; дневной лимит Worker учитывается для обоих вариантов.
• Распознаётся «заморозка» TLS-сессий после первых ~16 КБ (троттлинг Cloudflare у провайдеров) — тогда вперёд идёт HTTP.
• Разрез первого пакета против DPI: ClientHello уходит двумя TLS-записями с именем домена, разрезанным пополам, HTTP-запрос — двумя частями посередине Host. Внутри VPN-туннеля не применяется.
• Keepalive для сессий через Cloudflare и relay: соединения не рвутся на простое.
• DNS: если провайдер вместо адреса Cloudflare подсовывает заглушку, имя разрешается через DoH.
• Из 1.12.0: отсрочка TCP-резерва после неудач, пул WebSocket сначала пробует настоящий SNI, kwsN-1 только для медиа.
• «Проверить соединение» проверяет каждый маршрут (прямой, relay, Worker, Cloudflare по HTTP и TLS) до настоящего ответа Telegram и даёт совет по-русски.
