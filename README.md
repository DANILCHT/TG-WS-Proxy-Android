# TG WS Proxy для Android

MTProto-прокси для Telegram, который живёт прямо на телефоне. Ускоряет Telegram и помогает обойти блокировки: трафик идёт через WebSocket к собственным веб-эндпоинтам Telegram, а при фильтрации автоматически переключается на резервные каналы.

Сторонние серверы не нужны. Данные передаются в том же зашифрованном виде, что и обычно — приложение не расшифровывает переписку.

```
Telegram → локальный прокси (127.0.0.1:1443) → WebSocket/TLS → датацентр Telegram
```

## Возможности

- **Обход фильтрации на мобильном интернете** — разрез TLS-рукопожатия, подмена SNI, резервные каналы через Cloudflare
- **Работа мимо VPN** — пока прокси включён, трафик Telegram не идёт через активный VPN-туннель
- **Не VPN и не root** — слушает только локальный порт, трафик других приложений не трогает
- **Стабильный фон** — foreground-сервис типа `specialUse` без лимита 6 ч/сутки, wake- и Wi-Fi-локи
- **Пул соединений** — WebSocket-сессии открываются заранее, Telegram подключается мгновенно
- **Fake TLS** — локальное соединение можно замаскировать под TLS к произвольному домену
- **Автозапуск** после перезагрузки, живая статистика и логи прямо в приложении
- **Тихое уведомление** и **проверка обновлений на GitHub** — обе опции отключаются

Android 5.0+ (API 21). Размер APK — около 2 МБ.

## Установка

Скачайте `app-release.apk` со [страницы релизов](../../releases) и откройте на телефоне. Понадобится разрешить установку из неизвестных источников.

APK подписан самоподписанным сертификатом, поэтому Android покажет предупреждение — это нормально для любого приложения вне Google Play. Если сработает Play Protect, выберите «Установить всё равно».

## Использование

1. Нажмите **Запустить прокси**. На Android 13+ разрешите уведомления — без постоянного уведомления система убьёт сервис.
2. Нажмите **Открыть в Telegram** — прокси добавится автоматически по ссылке `tg://proxy`.
3. Если не сработало: **Скопировать ссылку** → отправьте её в «Избранное» в Telegram → нажмите на неё.

Ручная настройка: **Настройки** → **Данные и память** → **Прокси** → **Добавить прокси** → **MTProto**, сервер `127.0.0.1`, порт `1443`, secret — с главного экрана.

## Если Telegram не подключается

Откройте раздел **«Обход блокировок»** — у каждой настройки внутри приложения есть пояснение простым языком.

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| Разрезать TLS-рукопожатие | вкл. | Первый пакет уходит двумя частями, имя домена разрезано пополам. Обходит фильтры, читающие только первый пакет — обычный случай у мобильных операторов. На скорость не влияет. |
| Пауза между частями | `0` мс | 10–50 мс помогают против фильтров, которые собирают пакеты вместе. Добавляется к каждому новому соединению. |
| Сразу подставлять нейтральный домен | выкл. | Экономит 5–7 секунд на подключение, если сеть блокирует Telegram по имени домена. |
| Нейтральный домен | `sprinthost.ru` | Имя, которое видит сеть вместо домена Telegram. |
| Не пускать через VPN | вкл. | Соединения прокси идут мимо VPN-туннеля. Другие приложения не затронуты. |

Если фото и видео не грузятся — очистите поле **«Датацентры»** в разделе «Подключение MTProto». Такое встречается на аккаунтах без Premium.

**Что честно не работает:** разрез пакета не обманет DPI, который собирает весь TCP-поток перед анализом. Заблокировать сам VPN приложение не может — на Android без root это невозможно, оно лишь уводит свой трафик из туннеля. Если VPN в режиме lockdown запрещает выход мимо туннеля, приложение вернётся к работе через него и напишет об этом в лог.

## Уведомление и обновления

Раздел **«Уведомления и обновления»**:

- **Тихое уведомление** — убирает счётчики и кнопку «Стоп», прячет уведомление с экрана блокировки и сворачивает его в низ шторки. Полностью убрать нельзя: Android выключает фоновый сервис без уведомления. Кнопка «Системные настройки уведомлений» ведёт туда, где его можно скрыть совсем — прокси продолжит работать, но система будет останавливать его раньше.
- **Проверять обновления на GitHub** — включено по умолчанию, о чём приложение сообщает при первом запуске. Не чаще раза в сутки спрашивает у GitHub Releases, есть ли новая версия. Ничего не устанавливается без подтверждения: показывается версия, размер, список изменений и кнопки «Обновить» / «Пропустить эту версию» / «Позже». Выключается одним переключателем, проверить вручную можно кнопкой или через меню.

Обновление скачивается в кеш и передаётся системному установщику — Android всегда показывает свой экран подтверждения, тихая установка невозможна. При первом обновлении понадобится разрешение «установка неизвестных приложений», приложение откроет нужный экран само.

Обновление встанет поверх только если новый APK подписан тем же ключом. Релизы из этого репозитория подписаны одним ключом, но APK из других сборок поверх не установится.

## Сборка из исходников

Нужны JDK 17+ и Android SDK (platform 34, build-tools). Путь к SDK — в `local.properties`:

```properties
sdk.dir=/path/to/android/sdk
```

```shell
./gradlew :app:assembleDebug        # debug APK
./gradlew :app:assembleRelease      # release APK (подписанный, если есть keystore.properties)
./gradlew :app:testDebugUnitTest    # unit-тесты
./gradlew :app:lintDebug            # Android lint
```

На Windows — `gradlew.bat`. Готовый APK: `app/build/outputs/apk/`.

### Подпись release

Создайте `keystore.properties` рядом с `gradlew` (в git не попадает):

```properties
storeFile=tgwsproxy-release.jks
storePassword=...
keyAlias=tgwsproxy
keyPassword=...
```

Свой ключ:

```shell
keytool -genkeypair -v -keystore tgwsproxy-release.jks \
  -alias tgwsproxy -keyalg RSA -keysize 4096 -validity 10950
```

Без этого файла release собирается неподписанным. **Храните ключ и пароли:** обновление поверх установленного приложения возможно только тем же ключом.

## Сборка в GitHub Actions

Workflow `.github/workflows/android.yml` на каждый push запускает тесты, lint и debug-сборку, APK кладёт в артефакты. Подписанный release собирается, только если в репозитории заданы секреты:

`KEYSTORE_BASE64` (ключ в base64), `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` — в Settings → Secrets and variables → Actions.

Ручной запуск с `make_release=true` создаёт GitHub Release с APK.

## Как устроен код

- `core/` — протокол: `ProxyEngine` (приём подключений, выбор канала), `Bridge` (перекачка данных), `Obfuscated`/`Crypto` (MTProto-обфускация), `Pools` (пул сессий), `NetworkBinder` (обход VPN), `Fallback` (резервные каналы), `UpdateChecker`/`UpdateInstaller` (обновления)
- `net/` — транспорт: `RawWebSocket` (клиент RFC 6455), `WsFraming`, `Tls`, `TlsFragmenter` + `FragmentingSocket` (разрез рукопожатия), `FakeTls`
- `service/` — `ProxyService` (foreground-сервис), `BootReceiver` (автозапуск)
- `ui/` — `MainActivity`

86 unit-тестов покрывают криптографию, разбор конфигурации, обфускацию, Fake TLS, фрейминг WebSocket, разрез ClientHello и проверку обновлений.
